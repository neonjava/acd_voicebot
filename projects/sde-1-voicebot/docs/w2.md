# W2 Speech-to-Text / Transcription & Spoken Replies

Related to [issue #4](https://github.com/neonjava/acd_voicebot/issues/4), [issue #5](https://github.com/neonjava/acd_voicebot/issues/5), [issue #31](https://github.com/neonjava/acd_voicebot/issues/31), [issue #66](https://github.com/neonjava/acd_voicebot/issues/66), and [issue #85](https://github.com/neonjava/acd_voicebot/issues/85).

The Python package is `app`, rooted at `projects/sde-1-voicebot/backend/`. W2 delivers transcript domain schemas, a provider-neutral adapter protocol, a deterministic fake transcriber, an ordered segment accumulator with revision tracking, audio preprocessing, bounded retry policies, a local faster-whisper adapter with mock fallback, an end-to-end transcription orchestrator, a reproducible latency benchmark, and local text-to-speech spoken replies (`app.tts`).

## Week 4 Architecture & Hardening (Issue #85, Days 22–30)

Week 4 hardens transcription for the Day 30 release gate and adds spoken replies via local text-to-speech (`app.tts`):

```text
[User Speech] -> [W1 Audio] -> [W2 TranscriptionOrchestrator] -> [TranscriptEvent]
                                                                        │
                                                                        ▼
                                                             [W5 Conversation Turn]
                                                                        │ (TurnResponse.spoken_text)
                                                                        ▼
                                                             [W2 SpeechSynthesizer]
                                                                 ├─ MockSynthesizer (default, deterministic WAV)
                                                                 └─ PiperSynthesizer (local neural TTS, 16-bit mono)
```

### 2. Spoken Replies via Text-to-Speech (`app.tts`)

Enables Jarvis to speak its short conversational answers (`TurnResponse.spoken_text`):

- **`SpeechSynthesizer` Protocol**: `synthesize(text: str) -> bytes` returning canonical 16-bit mono WAV containers.
- **`MockSynthesizer`**: Pure Python, zero-dependency synthesizer using standard library `wave`. Generates a deterministic 16-bit mono waveform for testing and offline environments.
- **`PiperSynthesizer`**: High-quality local neural TTS using Piper (`tts` extra). Features lazy importing so default installations run cleanly without extra packages. Voice models are stored in local user cache (`~/.cache/piper`) and never committed.
- **Text Length Limit**: Enforces maximum text length of 300 characters. Text exceeding 300 characters is rejected with `TTSTextTooLongError`.
- **Safe Fallback**: If Piper or the voice model is missing, `TTSUnavailableError` is raised with error code `TTS_UNAVAILABLE` (mapped to HTTP 404/503 by W5 endpoints).

### 3. Provider Setup Guide

All providers run in mock mode by default. Real models are activated via configuration without code changes:

| Environment Variable | Default | Permitted Values | Description |
|---|---|---|---|
| `STT_PROVIDER` | `mock` | `mock`, `faster_whisper` | Active STT transcription engine |
| `STT_MODEL_SIZE` | `base` | `tiny`, `base`, `small`, `medium` | Faster-whisper model size |
| `STT_DEVICE` | `auto` | `auto`, `cpu`, `cuda` | Target compute device (auto detects CUDA via `ctranslate2`) |
| `STT_COMPUTE_TYPE` | `auto` | `auto`, `int8`, `float16` | Quantization type (auto selects float16 on GPU, int8 on CPU) |
| `STT_CONFIDENCE_THRESHOLD` | `0.4` | `0.0` .. `1.0` | Minimum confidence score for authoritative final text |
| `STT_FALLBACK_TO_MOCK` | `true` | `true`, `false` | Fall back to mock provider on model error |
| `STT_USE_SYSTEM_CERTS` | `0` | `0`, `1` | Opt-in to OS certificate store for HuggingFace downloads |
| `TTS_PROVIDER` | `mock` | `mock`, `piper` | Active text-to-speech engine |
| `TTS_VOICE` | `en_US-lessac-medium` | Voice name or `.onnx` path | Piper voice model name or path |
| `TTS_CACHE_DIR` | `~/.cache/piper` | Valid directory path | Directory for downloaded voice models |

### 4. Known Limitations

1. **Initial Model Download**: The first execution with real providers (`STT_PROVIDER=faster_whisper` or `TTS_PROVIDER=piper`) requires an active internet connection to download model weights. Subsequent runs execute completely offline.
2. **Spoken Text Boundary**: Spoken responses are strictly limited to $\le 300$ characters. Long responses must be summarized before speech synthesis.
3. **CPU vs GPU Latency**: On CPU, faster-whisper processes speech at approximately $\sim 0.15\text{x}$–$0.25\text{x}$ RTF. CUDA GPU acceleration achieves $\sim 0.03\text{x}$–$0.05\text{x}$ RTF.
4. **Mock Mode Acoustic Representation**: `MockSynthesizer` generates a synthetic test tone rather than acoustic phonetic speech to remain 100% dependency-free and deterministic.

## Week 3 Architecture (Issue #66, Days 15–21)

Week 3 makes transcription session-aware, resilient to provider failures, and connects it to upstream W1 `SpeechEvent` boundaries and the downstream W5 session event stream:

```text
[W1 SpeechEvents: wake -> speech_start -> speech_end]
       │
       ▼
[TranscriptionOrchestrator]
       │
       ├─ [AudioPreprocessor] (amplitude normalization, 16kHz PCM chunks)
       │
       ├─ [RetryPolicy] (bounded retries, timeout normalization)
       │
       ├─ [STT Provider]
       │       ├─ FasterWhisperAdapter (local faster-whisper, CPU int8 / CUDA)
       │       └─ FakeTranscriber (automatic mock fallback with ErrorEnvelope)
       │
       ├─ [SegmentAccumulator]
       │       ├─ Chronological ordering (start_ms, sequence_id, segment_id)
       │       ├─ Revision tracking for interims; exactly one final closes segment
       │       ├─ Configurable confidence threshold (default 0.4)
       │       └─ Low-confidence filtering from final text
       │
       └─ [W5 Session Event Stream] (published via event_sink)
```

### 1. Revisions, Finalization, and Session Awareness
- **Interim revisions**: Incoming interim segments (`is_final=False`) update previous drafts with the same `segment_id`, incrementing the revision counter.
- **Finalization**: Exactly one final segment (`is_final=True`) closes each segment. Once closed, the segment cannot regress to interim or accept late mutations.
- **Session ID preservation**: Every `TranscriptEvent` carries a matching `session_id` in both the envelope and payload. Mismatched or mixed sessions produce normalized error envelopes.

### 2. Confidence Threshold Handling (`TranscriptionConfig.confidence_threshold`)
- Configurable threshold (default `0.4`, environment variable `STT_CONFIDENCE_THRESHOLD`).
- Segments below the threshold are flagged as low-confidence.
- By default, `final_segments(include_low_confidence=False)` and `get_final_text(include_low_confidence=False)` exclude low-confidence segments so they are never sent on to downstream consumers (like reasoning or the UI) as authoritative final text without that explicit flag.

### 3. Local Faster-Whisper with Mock Fallback (`FasterWhisperAdapter`)
- **Lazy import**: `faster_whisper` is imported lazily inside `FasterWhisperAdapter._ensure_model_loaded()`. Environments without the `stt` extra run tests and mock mode cleanly without import errors.
- **Configuration**:
  - Model size: `base` (default, configurable via `STT_MODEL_SIZE`).
  - Device & compute: CUDA `float16` when available, otherwise CPU `int8` (configurable via `STT_DEVICE` and `STT_COMPUTE_TYPE`).
  - Language: `en` (default, configurable via `STT_LANGUAGE`).
- **Segment mapping**: Maps model segments to canonical `TranscriptSegment` payloads:
  - `start_ms` and `end_ms` relative to stream start.
  - `confidence` derived from `avg_logprob` ($e^{\text{avg\_logprob}}$) or model scores.
  - `is_final=True`.
- **Automatic mock fallback**: If `faster-whisper` fails to load (missing package, model download failure, CUDA out of memory, quota or network failure):
  - Emits a normalized `ErrorEnvelope` with code `TRANSCRIPTION_FALLBACK_TO_MOCK` (`retryable=False`).
  - Automatically routes the audio chunks to `FakeTranscriber`.
  - The fallback error is visible in the event stream, allowing callers to observe the fallback while the session continues seamlessly.

### 4. W1 SpeechEvent Boundaries & W5 Event Stream Integration
- **`process_speech_session(speech_events, chunks, ...)`**:
  - Consumes W1 `SpeechEvent` boundaries (`wake` $\to$ `speech_start` $\to$ `speech_end`).
  - Isolates and transcribes all `AudioChunk`s located within each active speech interval (`speech_start.at_ms` to `speech_end.at_ms`) as distinct utterances without merging.
  - Handles boundary edge cases gracefully: an unclosed `speech_start` without `speech_end` or duplicate `speech_start` emits a normalized `TRANSCRIPTION_UNMATCHED_SPEECH_BOUNDARY` error event and preserves the first speech start rather than dropping or overwriting silently.
- **Event stream publishing**:
  - `TranscriptionOrchestrator` accepts an `event_sink` callback (such as `SessionService.add_event`).
  - All emitted `transcript.segment` and `transcript.error` events are published directly to the session's ordered event buffer.

### 5. Clean Cancellation
- Calling `cancel(session_id)` records cancellation on the orchestrator and propagates it to the active adapter.
- The cancellation covers one utterance: the one in flight, or the next one if nothing is running. That utterance returns `[]`, nothing is added to the accumulator and nothing is published to the event sink, even if the cancel arrives while the adapter is still working.
- After the cancelled utterance is dropped, the flag is cleared in the orchestrator and the adapter, so the next utterance in the same session is transcribed normally. In `process_speech_session`, only the utterance that was running is dropped.
- `reset()` also clears any pending cancellation. Segment and event IDs keep counting after `reset()`, so a session never receives the same ID twice.

## Week 2 Architecture (Issue #31, Days 8–14)

Week 2 connects upstream W1 audio chunks through preprocessing, bounded retry boundaries, provider adapters, and an extended segment accumulator.

```text
[W1 AudioChunks] 
       │
       ▼
[AudioPreprocessor]  ── (amplitude normalization, resampling)
       │
       ▼
[RetryPolicy]        ── (bounded retries, positive timeout, error normalization)
       │
       ▼
[TranscriptionAdapter] (FakeTranscriber)
       │
       ▼
[TranscriptEvents]
       │
       ├──────────────────────────────────────────┐
       ▼                                          ▼
[SegmentAccumulator]                       [W5 Session Stream]
(order, revisions, deduplication, gaps)    (typed TranscriptEvent envelopes)
       │
       ▼
[W3 Reasoning Context]
(finalized TranscriptSegments -> ContextItems)
```

### 1. Transcription Orchestrator (`app.transcription.orchestrator`)

`TranscriptionOrchestrator` coordinates the full pipeline:
- **`process_chunks(chunks, session_id, correlation_id, timestamp, preprocess=True)`**:
  - Preprocesses incoming `AudioChunk` objects (amplitude normalization).
  - Invokes `TranscriptionAdapter` wrapped with `RetryPolicy`.
  - Ingests successful `TranscriptSegment` payloads into `SegmentAccumulator`.
  - Emits typed `TranscriptEvent` envelopes.
- **`get_transcript_text()`**: Returns concatenated text in chronological order.
- **`get_segments()` / `get_final_segments()`**: Returns accumulated segments ordered chronologically.
- **`get_revisions(segment_id)`**: Returns revision count for a segment ID.
- **`get_gaps(min_gap_ms)`**: Returns detected silence/pause gaps.
- **`cancel(session_id)` / `reset()`**: Safely halts or resets session state.
- **Session Lifecycle (W5 Note)**: One `TranscriptionOrchestrator` instance serves a single session; attempting to ingest segments from a second session raises `ValueError` from the accumulator unless `reset()` is called.
- **Batch Error Event IDs**: Every `process_chunks` call increments an internal batch counter, ensuring that retry error envelopes (`TRANSCRIPTION_RETRY_EXHAUSTED` and timeouts) receive unique, deterministic `event_id`s across batches within the same session.

### 2. Audio Preprocessing (`app.transcription.preprocessing`)

Deterministic, pure-Python preprocessing for `pcm_s16le` mono audio:
- **`normalize_amplitude(pcm, target_peak=0.95)`**:
  - Scales 16-bit signed samples to target peak amplitude in `(0.0, 1.0]`.
  - Prevents clipping: clamps samples to `[-32768, 32767]`.
  - Preserves silence: all-zero PCM is returned unmodified.
- **`resample_pcm(pcm, from_rate_hz, to_rate_hz=16000)`**:
  - Linear interpolation resampling between sample rates.
  - Preserves mono 16-bit encoding deterministically.
- **`AudioPreprocessor`**:
  - `process_chunk(chunk)`: Normalizes an `AudioChunk` while keeping byte formula `duration_ms * 32` intact.
  - `convert_external_audio(pcm, from_rate_hz, session_id, chunk_ms)`: Converts non-16kHz PCM to standard 16kHz `AudioChunk` sequences without loosening Week 1 contract validators.

### 3. Bounded Retry & Timeout Policy (`app.transcription.retry`)

- **`RetryPolicy(max_retries=2, retryable_codes=...)`**:
  - Enforces bounded attempts (`max_retries + 1`).
  - Retries transient errors (`retryable=True` or codes like `TRANSCRIPTION_TEMPORARY_ERROR`, `TRANSCRIPTION_TIMEOUT`).
  - Immediately rejects non-retryable errors (`retryable=False`, malformed payloads) without retry.
  - When retries are exhausted, emits a normalized `TRANSCRIPTION_RETRY_EXHAUSTED` error envelope with safe user messaging.
  - Safely normalizes unexpected driver exceptions to `TRANSCRIPTION_INTERNAL_ERROR`.
  - Provider output that is not a list of `TranscriptEvent` values becomes a non-retryable `TRANSCRIPTION_MALFORMED_OUTPUT` error. The whole batch is rejected, the raw output is not exposed, and segments from earlier attempts are kept.
  - **Timeout Handling**: Timeouts are handled when the adapter raises `TimeoutError`. In Week 2 mock mode, `FakeTranscriber.timeout_seconds` is validated for contract compliance but not actively enforced with blocking wall-clock sleeps, keeping tests deterministic and fast.

### 4. Extended Segment Accumulator (`app.transcription.accumulator`)

Extended for Week 2 requirements:
- **Chronological ordering**: Sorts strictly by `(start_ms, sequence_id, segment_id)`.
- **Out-of-order arrivals**: Segments arriving out of chronological order are properly sorted.
- **Revision tracking**: Updates text on the same `segment_id` and records `revisions_count(segment_id)`.
- **Stale interim rejection**: Interim updates with a lower `sequence_id` arriving after a newer interim are dropped.
- **Regression prevention**: Final segments cannot regress back to interim.
- **Duplicate suppression**: Exact duplicate events are ignored without duplicate text or revision increments.
- **Gap detection**: `gaps(min_gap_ms)` identifies silence or pauses between segments.
- **Session safety**: Rejects events with mixed `session_id`s with `ValueError`.

## Transcription Contracts (`app.contracts.transcription`)

Inherits from shared models in `app.contracts.common`:

- **`TranscriptSegment`**:
  - `segment_id`: Nonempty string (`min_length=1`, pattern `r"\S"`).
  - `session_id`: Nonempty string (`min_length=1`, pattern `r"\S"`).
  - `sequence_id`: Strict integer `>= 0`.
  - `start_ms` / `end_ms`: Strict integers `>= 0`, enforcing `end_ms >= start_ms`.
  - `text`: Nonblank recognized or synthetic transcript text.
  - `confidence`: Finite float in `[0.0, 1.0]` or `None`.
  - `language`: Nonempty language tag (default `"en"`).
  - `is_final`: Strict boolean indicating interim vs final status.
  - `extra="forbid"`: Rejects unknown fields.

- **`TranscriptEvent`**: Typed envelope inheriting `EventEnvelope[Union[TranscriptSegment, ErrorEnvelope]]`.
  - `producer`: Literal `"transcription"`.
  - `event_type`: Literal `"transcript.segment"` or `"transcript.error"`.
  - `schema_version`: Literal `"1.0"`.
  - Strict pairing:
    - `"transcript.segment"` requires `payload: TranscriptSegment` and matching `session_id`.
    - `"transcript.error"` requires `payload: ErrorEnvelope` and matching `correlation_id`.
  - Enforces timezone-aware UTC timestamp.

## Integration & Handoffs

- **W1 (Audio):** Consumes real `make_fake_pcm` and `chunk_pcm`. `AudioPreprocessor` normalizes amplitude and resamples non-16kHz external audio without weakening canonical 16kHz `AudioChunk` validation.
- **W3 (Reasoning):** `TranscriptionOrchestrator.get_final_segments()` outputs finalized `TranscriptSegment` objects mapped via `context_item_from_transcript` into `ContextItem` with `source_id=segment_id`, `kind="transcript"`.
- **W5 (Backend & Sessions):** Emits validated `TranscriptEvent` envelopes ready for inclusion in `MockSessionResponse.events`.
- **W6 (Frontend):** Accumulator ordering and revision semantics match frontend `TranscriptTimeline` badges (`Interim`, `Final`, `Revised`).
