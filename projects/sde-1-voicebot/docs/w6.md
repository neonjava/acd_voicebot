## Architecture and Design Decisions

### 1. Electron Desktop Companion Window (Bottom-Right Work Area)
- **Bottom-Right Corner Positioning**:
  - `frontend/electron/bounds.ts` and `bounds.cjs` define `getCompanionBounds(display, expanded)` (with `getNotchBounds` aliased for full backwards compatibility).
  - Window coordinates anchor to the bottom-right corner of the display's usable `workArea` (respecting taskbars on Windows and docks on macOS/Linux):
    - **Collapsed State**: Compact `72×72 px` glowing knot pill at `x = displayX + width - 72`, `y = displayY + height - 72`.
    - **Expanded State**: Out-of-the-way companion card at most `380×320 px` at `x = displayX + width - 380`, `y = displayY + height - 320`.
  - Factors in secondary monitor origin coordinates (`display.x`, `display.y`), clamps gracefully on smaller displays, never goes full screen (`fullscreenable: false`), and avoids taskbar clutter (`skipTaskbar: true`).
  - **Linux Wayland Support**: Automatically injects `--ozone-platform=x11` switch on Linux to ensure always-on-top positioning works seamlessly under GNOME Wayland via XWayland.

### 2. Mascot Reactive States & Tethered Thread
- **Mascot Reactivity (`Mascot.tsx`)**:
  - A glowing thread knot that visualizes assistant status across 5 discrete states derived from `CaptureStatus`, turn events, and browser actions:
    1. `idle`: Resting cyan glow (`#38bdf8`), ready for interaction.
    2. `listening`: Pulsing emerald ring (`#34d399`), active microphone capture / "Hey Jarvis" wake word.
    3. `thinking`: Rotating violet spiral (`#a78bfa`), query processing & LLM inference.
    4. `working`: Amber orbital pulse (`#f59e0b`), browser task execution in progress.
    5. `done`: Steady green knot (`#22c55e`), task successfully completed.
  - **Reduced Motion Support**: Fully respects `@media (prefers-reduced-motion: reduce)`, disabling CSS keyframe rotations and pulses while maintaining clear color indicators.
  - **Accessibility**: Includes `role="status"` and hidden `aria-live="polite"` text announcing every state transition to assistive technologies.

### 3. Speech Bubble & Conversational Turn Integration
- **Speech Bubble Tether (`SpeechBubble.tsx`)**:
  - Visual speech bubble tethered to the mascot by a curved SVG bezier thread (`M 18,24 C 28,12 40,8 60,6`).
  - Renders user requests (`"You: open my attendance page"`) and parses all Week 4 `TurnResponse` variants:
    - **`answer`**: Displays concise answer, source citations (`psutil`, web sources), and spoken caption indicator (`Spoken: "..."`).
    - **`clarify`**: Displays clarification prompt with dedicated reply input.
    - **`proposal`**: Displays structured plan proposal with one-line task risk explanation and immediate **Approve / Reject** buttons.
    - **`error`**: Clear user-safe error alert with actionable retry trigger.
- **Focus Trap & Execution Guarantee**:
  - The proposal approval dialog traps keyboard focus between **Approve** and **Reject** buttons using `Tab` and `Shift+Tab`.
  - Pressing <kbd>Escape</kbd> immediately rejects the proposal.
  - **Execution Guarantee**: Unit and end-to-end tests prove that rejecting an approval request records `approval_rejected` and strictly results in **zero tool executions** (`executionCount === 0`).

### 4. Live Step Chips Sequence (`StepChips.tsx`)
- Displays real-time browser automation execution steps as compact sequence chips:
  - `✓ Read page` (Completed, green badge)
  - `⚡ Click Attendance` (In-progress, amber badge)
  - `◌ Read results` (Pending, slate badge)
  - `✕ Error` (Failed, red badge)
- Listens to `browser.action` events (`started`, `completed`, `failed`) and updates live without full re-renders.

### 5. Accessibility (a11y) & Keyboard Navigation
- **Keyboard Shortcuts**:
  - <kbd>Alt+N</kbd>: Toggle companion between collapsed pill (72×72) and expanded card (380×320).
  - <kbd>Alt+L</kbd>: Trigger "Hey Jarvis" voice listening.
  - <kbd>Alt+S</kbd>: Start live session.
  - <kbd>Alt+P</kbd>: Pause active session.
  - <kbd>Alt+R</kbd>: Resume paused session.
  - <kbd>Alt+X</kbd>: Stop active session.
  - <kbd>Escape</kbd>: Reject pending approval or collapse card.
- **ARIA Live Regions**:
  - `aria-live="polite"` on status messages, transcript captions, and mascot state updates.
  - `aria-live="assertive"` on error alerts and approval prompts.

### 6. Demo Mode (Zero Backend Keys)
- `FixtureSessionClient` provides a full, deterministic demo mode requiring no real microphone, no screen capture, and no external API keys.
- Supports scripted interactions:
  - *"what's using the most ram?"* -> answers with `psutil` system metrics and spoken text.
  - *"open my attendance page"* -> generates browser proposal, waits for approval, streams `browser.action` steps on approval, or records zero execution on rejection.
  - *"simulate failure"* -> exercises offline/error recovery banner.

## User Troubleshooting Guide

### 1. Microphone Permission Denied or Unavailable
- **Symptoms**: Mascot fails to enter `listening` state when clicking Listen or pressing <kbd>Alt+L</kbd>; error banner indicates `AUDIO_DEVICE_UNAVAILABLE` or `PERMISSION_DENIED`.
- **Causes**:
  - OS-level microphone access is blocked for Electron / browser.
  - Hardware microphone is unplugged or disabled in sound settings.
- **Resolution**:
  - **Windows**: Open `Settings > Privacy & Security > Microphone`, ensure *Microphone access* and *Let desktop apps access your microphone* are enabled.
  - **Linux**: Check PulseAudio/PipeWire input volume with `pavucontrol` or `wpctl status`. Ensure the user is in the `audio` group.
  - **Fallback**: The companion fully supports typed conversational queries via the bottom input box (<kbd>Enter</kbd> to submit) without requiring a microphone.

### 2. Backend Offline or Unreachable
- **Symptoms**: Start button disabled with tooltip *"Waiting for backend to become ready..."*; error banner shows `DEPENDENCY_UNAVAILABLE` or `Failed to fetch`.
- **Causes**:
  - The Python backend sidecar has not finished initializing or failed to bind the port.
  - Custom `VOICEBOT_PORT` mismatch between frontend proxy and backend.
- **Resolution**:
  - Verify backend output prints the exact readiness token: `VOICEBOT_READY: http://127.0.0.1:<port>`.
  - In development, start backend manually:
    ```sh
    cd projects/sde-1-voicebot/backend
    uv run python -m app
    ```
  - If using a custom port, set `VOICEBOT_PORT=<port>` in both terminals before running.

### 3. Browser Extension Not Connected
- **Symptoms**: Browser task proposals are approved, but step chips remain pending; no `browser.action` events stream into the UI.
- **Causes**:
  - Chrome / Chromium browser extension (W1) is not installed or disconnected from the native messaging bridge.
- **Resolution**:
  - Ensure Chrome extension is loaded in developer mode from `projects/sde-1-voicebot/extension/`.
  - In Demo Mode (`FixtureSessionClient`), browser actions are automatically simulated, allowing full verification without the extension.

### 4. Reconnection with Exponential Backoff & Deduplication
- **Symptoms**: Temporary network glitch causes live captions to pause; UI displays `Connection dropped, reconnecting...`.
- **Automatic Recovery**:
  - The client automatically retries connecting with capped exponential backoff (1s, 2s, 4s, 8s, up to 10s max).
  - Upon reconnection, missed events are requested via `GET /api/sessions/{id}/events?from_sequence={count}`.
  - Replayed events pass through `seenEventIds` deduplication, guaranteeing **zero duplicate** transcript segments or audit chips.
- **Manual Override**: Click the **↻ Reconnect** button in the companion header to force an immediate reconnection cycle.

### 5. Wayland vs. XWayland Window Positioning (Linux)
- **Symptoms**: On GNOME Wayland, the companion window spawns in the center of the screen instead of the bottom-right corner, or always-on-top does not persist.
- **Resolution**:
  - Electron uses `--ozone-platform=x11` (configured in `main.cjs`) to run under XWayland, where window positioning coordinates (`x`, `y`) and `setAlwaysOnTop(true, 'screen-saver')` are strictly honored.
  - Ensure `xwayland` package is installed (`sudo dnf install xorg-x11-server-Xwayland` on Fedora or `sudo apt install xwayland` on Ubuntu).

### 6. Windows Desktop Work Area & DPI Scaling
- **Symptoms**: On high-DPI displays or multi-monitor setups with secondary taskbars, the collapsed pill appears partially covered by the taskbar.
- **Resolution**:
  - `bounds.ts` queries `display.workArea` rather than `display.bounds`. The work area automatically subtracts the taskbar height and position (top, bottom, left, or right).
  - Monitor origin offsets (`display.x`, `display.y`) are added to preserve precise bottom-right corner docking on secondary monitors.
