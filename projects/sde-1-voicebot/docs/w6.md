# W6 Frontend — Accessible Mock Voicebot UI (Week 1)

Related to [issue #7](https://github.com/neonjava/acd_voicebot/issues/7).

W6 delivers the React + TypeScript frontend application located at `projects/sde-1-voicebot/frontend/`. It provides an accessible, fully testable mock interface that visualizes voicebot sessions, simulates microphone permissions, orders transcript segments, and communicates with W5's mock session backend over HTTP.

## Architecture and Design Decisions

- **Framework & Tooling**: React 18, TypeScript 5, Vite 5, Vitest, React Testing Library, and jsdom.
- **Mock-First & Accessible**:
  - Prominent **Mock Mode Banner** indicating synthetic testing mode.
  - Semantic HTML landmarks (`<header>`, `<main>`, `<section>`, `<aside>`).
  - ARIA attributes (`role="status"`, `role="alert"`, `aria-live="polite"`, `aria-live="assertive"`, `aria-describedby`).
  - Keyboard accessibility with visible focus and global shortcuts: <kbd>Alt+S</kbd> to Start, <kbd>Alt+X</kbd> or <kbd>Esc</kbd> to Stop.
- **Simulated Hardware State**:
  - Visible radio selector for mock microphone permission states: `Granted`, `Prompt`, `Denied`, and `Unavailable`.
  - Blocks session starts with clear accessible alerts when permission is `denied` or `unavailable`.
  - **Zero device access**: Never invokes browser `getUserMedia()` or accesses audio devices.
- **Direct Canonical Fixture Usage**:
  - Directly imports `projects/sde-1-voicebot/backend/tests/fixtures/session_response.json` rather than maintaining a separate TypeScript duplicate, ensuring 100% wire parity with backend tests.
- **Typed Wire Contracts & Strict Runtime Validation**:
  - Typed models for `MockSessionResponse`, `EventEnvelope`, `TranscriptSegment`, `AudioChunkMetadata`, and `ErrorEnvelope` directly aligning with `docs/contracts.md`.
  - Full runtime schema validation in `src/utils/validation.ts` preventing unvalidated casting or corrupted state from entering the UI.
  - Strictly enforces the agreed PCM byte size formula for 16000Hz 16-bit mono: `size_bytes === duration_ms * 32` bytes. Mismatched byte sizes throw `MalformedResponseError`.
- **Transcript Error Surfacing**:
  - Inspects incoming envelopes for `transcript.error`. If present, surfaces the error envelope accessibly, transitions `uiState` to `failed`, and avoids reporting success.
- **Session State Hygiene**:
  - Starting a new session immediately clears prior transcript segments, prior audio chunk summaries, and prior session IDs, preventing stale data from lingering in the UI.
- **Ordered Transcript Accumulator**:
  - Implements the contract accumulation rules: sorts by `start_ms` ascending, then `sequence_id`, then `segment_id`.
  - Upgrades interim segments to final when matching `segment_id` is received.
  - Prevents regression of final segments back to interim status.
  - Ignores duplicate segments.
- **Late Response Cancellation**:
  - Uses an incrementing session token and `AbortController`.
  - If a user triggers "Stop", in-flight HTTP requests are aborted and late responses are discarded without mutating the timeline or UI status.
- **Unified Client Boundary (`SessionClient`)**:
  - `HttpSessionClient`: Connects to `POST /api/sessions/mock` with empty body `{}` via the configured Vite proxy (`127.0.0.1:8000`).
  - `FixtureSessionClient`: Returns baseline synthetic data conforming exactly to the canonical `backend/tests/fixtures/session_response.json`.
  - Supports runtime switching between HTTP API and Synthetic Fixture modes.

## Two-Terminal Demo Instructions & Integration Status

To test integration between the frontend and the mock backend server:

### Terminal 1: Backend Server (W5)

From the project root:

```sh
cd projects/sde-1-voicebot/backend
python -m app
# Or with uv:
uv run python -m app
```

Backend will start on `http://127.0.0.1:8000` exposing `/api/health`, `/api/ready`, and `POST /api/sessions/mock`.

### Terminal 2: Frontend Server (W6)

From the project root:

```sh
cd projects/sde-1-voicebot/frontend
npm run dev
```

Open `http://localhost:5173` in any modern web browser. The Vite development proxy automatically routes all `/api/*` requests to `http://127.0.0.1:8000`.

### Verifying UI & Client Behavior:
1. Ensure the **Mock Mode** banner is visible at the top.
2. Under **Simulated Microphone Permission**, verify "Granted" is selected.
3. Click **Start Session** (or press <kbd>Alt+S</kbd>).
4. Observe the session state transition: `IDLE` → `CONNECTING` → `COMPLETED`.
5. Verify the **Ordered Transcript Timeline** displays the final segment:
   - Time: `[0ms – 1000ms]` (seq #0)
   - Status: `Final`
   - Confidence: `100%`
   - Text: `"Hello from the mock voicebot."`
6. Verify the **Received Audio Events** list displays the wire metadata for `event-audio-0`:
   - `16000Hz | 32000 bytes` (duration: 1000ms).
7. Test simulated denial: Switch permission to "Denied", click "Start Session", and observe the accessible `SIMULATED_MIC_DENIED` alert without network requests.
8. Test Stop controls: Click "Start Session" then immediately click "Stop Session" (or press <kbd>Esc</kbd>) to observe cancellation.

## Integration Results

- **Shared Schema Alignment**:
  - Uses the canonical backend fixture directly from `backend/tests/fixtures/session_response.json`.
  - Wire projection payload `audio.chunk` contains metadata (`sequence_id`, `start_ms`, `duration_ms`, `sample_rate_hz`, `channels`, `size_bytes`) without raw PCM, with byte size verified against duration.
  - Transcript segment payload matches Megha's canonical specification (`segment_id="session-demo-segment-0"`, `text="Hello from the mock voicebot."`, `confidence=1.0`, `is_final=true`).
- **Error Normalization & Surfacing**:
  - Backend errors returning `ErrorEnvelope` (e.g. HTTP 422/500) are parsed and displayed accessibly with user-safe messages, error codes, and correlation IDs.
  - Session events containing `transcript.error` transition the UI to `failed` and render the error envelope accessibly without reporting success.
  - Malformed responses trigger typed `MalformedResponseError` alerts.

## Limitations & Future Work

- **Finite Mock Run Only**: Currently executes single finite mock sessions (`POST /api/sessions/mock` returning `state: "completed"`). Real-time streaming over WebSockets or SSE is planned for subsequent weeks.
- **Simulated Hardware**: Audio capture permissions and device availability are mocked in software. Real microphone capture via Web Audio / MediaStream is deferred past Week 1.
- **In-Memory Transcript State**: Transcripts are maintained in memory during the active browser session; persistence and historical playback will be implemented in future milestones.
