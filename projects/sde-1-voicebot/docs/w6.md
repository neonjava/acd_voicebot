# W6 Frontend — Accessible Voicebot UI (Week 2)

Related to [issue #7](https://github.com/neonjava/acd_voicebot/issues/7).

W6 delivers the React + TypeScript frontend application located at `projects/sde-1-voicebot/frontend/`. It provides an accessible, fully testable interface that visualizes voicebot sessions, handles pause/resume lifecycle controls with verified backend state indicators, renders interim and finalized transcripts with revisions and duplicate handling, surfaces synthetic screen-context sources (OFF by default), and communicates honestly with backend services over HTTP and verified fixtures.

---

## Architecture and Design Decisions

- **Framework & Tooling**:
  - React 18, TypeScript 5, Vite 5, Vitest, React Testing Library, and jsdom.
- **Mock-First & Strict Safety Enforcement**:
  - Prominent **Mock Mode Banner** indicating synthetic simulation mode.
  - **Zero device access**: Real microphone capture (`getUserMedia()`) and real screen capture (`getDisplayMedia()`) are strictly forbidden and never invoked.
  - Software-based permission simulator (`Granted`, `Prompt`, `Denied`, `Unavailable`) blocking unauthorized sessions with accessible alerts.
- **Pause & Resume Controls with Actual Backend Session-State Indicators**:
  - Interactive Pause and Resume buttons reflecting real lifecycle states.
  - **Dual State Indicators**:
    - `UI State`: Client view lifecycle (`idle`, `connecting`, `active`, `paused`, `completed`, `failed`).
    - `Backend State`: Actual verified backend session state (`created`, `active`, `paused`, `stopping`, `completed`, `failed`, `expired`).
  - **Single Instance Persistence**:
    - Retains a stable `FixtureSessionClient` instance across Start → Pause → Resume in built-in mode so that verified state transitions (`active <-> paused`) persist across consecutive user actions without state resetting.
  - **No False Optimism on Stop**:
    - Frontend strictly does not claim local toggles represent actual backend state. Attempting pause/resume against HTTP mode when upstream endpoints are unimplemented throws `DEPENDENCY_UNAVAILABLE`, preserving honest backend state reporting.
    - On local Stop / cancellation, backend state is safely reset (`Backend: not_started`) and never falsely marked as `Backend: completed`.
  - **Strict In-Flight Request Cancellation & Late Response Hygiene**:
    - In-flight pause and resume requests track session action tokens; if the session is stopped or superseded while a pause/resume request is pending, late success and error responses are strictly discarded and never corrupt UI or backend state.
  - Full keyboard shortcut support:
    - <kbd>Alt+S</kbd>: Start Session
    - <kbd>Alt+P</kbd>: Pause Active Session
    - <kbd>Alt+R</kbd>: Resume Paused Session
    - <kbd>Alt+X</kbd> or <kbd>Esc</kbd>: Stop / Abort Session
- **Accessible Loading, Offline, and Error States**:
  - Live loading spinners (`role="status"`, `aria-live="polite"`) during connection and pause/resume transitions.
  - Automatic browser connectivity tracking via `window.addEventListener('online' | 'offline')`.
  - Accessible offline warning banners and client-side rejection of network requests when offline.
  - Normalized backend error envelopes (`ErrorEnvelope`) displaying user-safe messages, error codes, and correlation IDs.
- **Interim/Final Transcripts, Revisions, Confidence, Ordering, and Deduplication**:
  - Visual badges distinguishing `Interim` (with animated status indicator) and `Final` segments.
  - `Revised` badge with revision counter whenever interim segment text is updated by a subsequent sequence under the same segment ID.
  - Strict deduplication ignoring exact duplicate segment events.
  - Deterministic timeline ordering: `start_ms` ascending, then `sequence_id`, then `segment_id`.
  - Finalized segments protected against regressions back to interim.
  - Confidence score formatting (`Confidence: 98%`), gracefully treating `null` as `"unknown"`.
- **Screen-Context Panel with Source References (W3 Parity)**:
  - Accessible panel with switch toggle (`role="switch"`, `aria-checked`), **OFF by default** (`capture_enabled: false`).
  - When OFF, clearly announces that synthetic frame capture is inactive and real screen capture (`getDisplayMedia()`) is never invoked.
  - When toggled ON (`capture_enabled: true`), displays synthetic frame (`frame-demo-0`), UTC timestamp, and context items with source references (`source_id`, `locator`, `kind`).
  - Projects finalized transcript segments into context items with `kind="transcript"`.
- **Typed Wire Contracts & Strict Runtime Validation**:
  - TypeScript types in `src/types/contracts.ts` mirroring `docs/contracts.md` and shared backend models (`SessionLifecycleState`, `SourceReference`, `ContextItem`, `ScreenContext`, `ReasoningResult`).
  - Runtime validation in `src/utils/validation.ts` validating all incoming payloads before state ingestion.
  - Enforces the agreed PCM byte size formula for 16000Hz 16-bit mono: `size_bytes === duration_ms * 32` bytes. Mismatched byte sizes throw `MalformedResponseError`.
- **Direct Canonical Fixture Usage & Multi-Fixture Support**:
  - Reuses the canonical `backend/tests/fixtures/session_response.json` for completed baseline parity.
  - Includes a Week 2 active streaming fixture (`week2StreamingSessionResponse`) demonstrating active sessions, interim updates, text revisions, duplicates, and pause/resume lifecycle.

## Two-Terminal Demo Instructions & Integration Status

To run the full two-terminal demonstration:

### Terminal 1: Backend Server (W5)

From the repository root:

```sh
cd projects/sde-1-voicebot/backend
python -m app
# Or with uv:
uv run python -m app
```

Backend starts on `http://127.0.0.1:8000` exposing `/api/health`, `/api/ready`, and `POST /api/sessions/mock`.

### Terminal 2: Frontend Server (W6)

From the repository root:

```sh
cd projects/sde-1-voicebot/frontend
npm run dev
```

Open `http://localhost:5173` in any modern web browser. The Vite proxy forwards `/api/*` requests to `http://127.0.0.1:8000`.

### Verifying Week 2 Behaviors in the UI:

1. **Verify Initial State & Controls**:
   - Ensure the **Mock Mode Banner** is visible.
   - Verify **Screen Context** switch is **OFF** by default.
   - Verify UI state indicator shows `UI: IDLE` and Backend state shows `BACKEND: NOT_STARTED`.
2. **Test Active Session Lifecycle with Fixture Mode**:
   - Under **Client Source**, select **Synthetic Fixture (Week 2 Active Streaming)**.
   - Click **Start Session** (or press <kbd>Alt+S</kbd>).
   - Observe state transition to `UI: ACTIVE` and `BACKEND: ACTIVE`.
   - Observe **Ordered Transcript Timeline**:
     - Finalized segment with `Revised (1 rev)` badge: `"Checking the system status and metrics now."`
     - Active interim segment with pulsing `Interim` badge: `"Voicebot session is actively listening"`.
     - Exact duplicate event was safely ignored without duplicated DOM elements.
   - Click **Pause** (or press <kbd>Alt+P</kbd>):
     - UI transitions to `UI: PAUSED` and `BACKEND: PAUSED` on the same fixture client instance.
     - Pause button is disabled; Resume button is enabled.
   - Click **Resume** (or press <kbd>Alt+R</kbd>):
     - UI transitions to `UI: ACTIVE` and `BACKEND: ACTIVE`.
     - Resume button is disabled; Pause button is enabled.
   - Click **Stop** (or press <kbd>Alt+X</kbd> or <kbd>Esc</kbd>):
     - Session stops cleanly; UI returns to `UI: IDLE` and backend indicator resets to `BACKEND: NOT_STARTED` (never claiming `completed`).
3. **Verify Screen Context & Source References**:
   - Click the **Screen Context** switch to toggle **ON**.
   - Observe synthetic frame header (`frame-demo-0`), timestamp, and source reference cards (`source_id: screen-status`, `locator: demo-dashboard`, `kind: synthetic_screen`).
   - Toggle switch **OFF** and verify synthetic frame details are cleanly hidden.
4. **Test Honest HTTP Reporting & Dependency Handling**:
   - Under **Client Source**, select **HTTP API (Vite proxy to :8000)**.
   - Click **Start Session**: receives completed mock session from backend.
   - Observe `BACKEND: COMPLETED`.
   - Click **Pause**: Because backend endpoints for pause are not yet exposed in `app/main.py`, client raises `DEPENDENCY_UNAVAILABLE`.
   - Notice the accessible error alert is shown and **Backend state indicator does NOT falsely claim paused**, maintaining complete honesty.

## Upstream Blockers & Dependency Coordination (Hemanth / W5)

In accordance with repository instructions:
> *"Do not invent API routes, duplicate models, modify backend files, or claim local toggles represent actual backend state. Coordinate missing dependencies with Hemanth."*

1. **Missing Pause/Resume Lifecycle Endpoints**:
   - Backend `backend/app/main.py` currently only exposes `/api/health`, `/api/ready`, and `POST /api/sessions/mock` (which executes a finite completed batch run).
   - Upstream endpoints to pause an active session (e.g., `POST /api/sessions/{session_id}/pause`) or resume a paused session (e.g., `POST /api/sessions/{session_id}/resume`) have not yet been published by W5.
   - **Frontend Status**: `HttpSessionClient` deliberately raises `BackendError` with code `DEPENDENCY_UNAVAILABLE` when pause/resume are invoked in HTTP mode. The frontend does not invent uncommitted API routes. Verified lifecycle transitions (`active <-> paused`) are fully implemented and verified via `FixtureSessionClient`.
2. **Live Streaming Transport**:
   - Backend streaming transport (WebSockets / SSE) for real-time chunk streaming is pending W5/W4 integration. `TranscriptAccumulator` is ready to ingest streaming events as they arrive.
