# W6 Frontend & UX: Live Backend Connection, Workflow Progress & Approval Dialog (Week 3)

Related to [issue #70](https://github.com/neonjava/acd_voicebot/issues/70) (and #7).

W6 delivers the React + TypeScript frontend and Electron desktop notch co-pilot located at `projects/sde-1-voicebot/frontend/`. Week 3 moves the UI to a live backend connection with reconnect and replay, workflow progress tracking, an approval dialog with risk explanations, privacy settings, and transitions the client into an Electron desktop app shaped as a notch at the top-centre of the screen (like a Mac notch or iPhone Dynamic Island).

## Architecture and Design Decisions

### 1. Electron Desktop Notch Co-Pilot
- **Top-Centre Frameless Desktop Notch**:
  - `frontend/electron/main.cjs` creates one frameless, transparent, always-on-top window anchored to the top centre of the primary display (`y = 0`).
  - **Collapsed State**: ~200×36 px compact pill showing animated status dot, listening badge, and expand toggle.
  - **Expanded State**: At most 480×360 px dropdown notch showing session controls, live captions, workflow progress, approval requests, and privacy settings.
  - Non-resizable by the user, non-fullscreenable (`fullscreenable: false`), and does not clutter the taskbar (`skipTaskbar: true`).
  - **Wayland / Linux Support**: Appends `--ozone-platform=x11` switch on Linux to ensure always-on-top and window positioning work reliably on GNOME Wayland under XWayland.
  - **Pure Window Bounds Function**:
    - `getNotchBounds(display, expanded)` in `frontend/electron/bounds.ts` (and `bounds.cjs`) calculates exact window bounds from display dimensions.
    - Verified by pure unit tests across 1366×768, 1920×1080, 2560×1440, and custom small displays: guarantees window is strictly centered at `y: 0` and bounds never exceed 480×360 px.

### 2. Backend Sidecar & Launch Token Boundary
- **Secure Process Lifecycle**:
  - `main.cjs` / `sidecar.ts` spawns the Python backend (`uv run python -m app` from `backend/`) with a cryptographically secure random `VOICEBOT_LAUNCH_TOKEN` (`vbt-...`).
  - Listens for the backend ready line (`Application startup complete` or `Uvicorn running on`) before triggering renderer connectivity.
  - Sanitizes all stdout/stderr output chunks using `sanitizeLogOutput`, replacing secret launch tokens with `[REDACTED_LAUNCH_TOKEN]`.
  - Handles clean termination on window exit or application shutdown (`taskkill /F /T` on Windows, `SIGTERM` on Linux/macOS).
- **Preload Bridge Security**:
  - `frontend/electron/preload.cjs` exposes `window.voicebot` to the renderer with `contextIsolation: true` and `nodeIntegration: false`.
  - Exposes `isElectron: true`, `getToken()`, and `setWindowExpanded(boolean)`.
  - **Zero Storage Leakage**: The launch token is never logged to disk or console and is **never stored in browser `localStorage`**.

### 3. Live Backend Connection, Reconnect & Replay
- **Bearer Token Authorization**:
  - `HttpSessionClient` automatically retrieves the launch token via `window.voicebot.getToken()` or constructor options and sends `Authorization: Bearer <token>` on all requests per contracts.md.
- **Reconnect with Zero Duplicates**:
  - When connection drops or stream stalls, the client reconnects with backoff and requests `GET /api/sessions/{id}/events?from_sequence={count}`.
  - Replayed events are verified against an in-memory `seenEventIds` registry. Duplicate events are discarded, and only new events update the transcript timeline and audit steps.

### 4. Workflow Progress Panel (W4 Parity)
- Compact progress panel inside the expanded notch driven by `workflow.audit` events (`AuditEvent`).
- Renders step-by-step audit states with color-coded status badges:
  - `step_succeeded` (Green)
  - `step_failed` (Red)
  - `step_retried` (Yellow)
  - `approval_granted` (Blue)
  - `approval_rejected` (Red)
  - `workflow_cancelled` (Gray)

### 5. Approval Dialog with Risk Explanation
- **One-Line Risk Explanation**:
  - Clearly explains what will happen and why approval is needed: *"Step {step_id} in plan {plan_id} will perform consequential system actions that require explicit human consent."*
- **Execution Prevention Guarantee**:
  - Approving records `approval_granted` and permits step execution.
  - **Rejecting never triggers execution**: Unit and client tests prove that rejecting an approval request records `approval_rejected`, prevents tool invocation, and leaves tool execution counts at zero.

### 6. Privacy Settings (Screen Awareness)
- Clear toggle switch in the notch console, **OFF by default** (`aria-checked="false"`, `capture_enabled: false`).
- Clearly visible status indicator: `Screen Context: OFF (capture_enabled: false)` vs `Screen Context: ON (capture_enabled: true)`.
- When turned OFF, stops synthetic frame ingestion and clears context. Real screen capture (`getDisplayMedia()`) is strictly prohibited.

### 7. Week 3 Reviewer Findings Addressed (PR #70 / #79)
1. **Approval Route Integration & Dependency Blocker (Finding 1)**: `HttpSessionClient` wires pending approvals (`GET /api/sessions/{id}/approvals`) and decisions (`POST /api/sessions/{id}/approvals/{approval_id}`). If upstream W5 routes return 404 or 501, throws `BackendError` with code `DEPENDENCY_UNAVAILABLE` rather than generic network failure.
2. **Launch Token Boundary (Finding 2)**: Cryptographically secure launch token generated in `token.cjs`, passed via env `VOICEBOT_LAUNCH_TOKEN`, sanitized from all logs with `[REDACTED_LAUNCH_TOKEN]`, and never stored in `localStorage`.
3. **Backend Readiness Gating (Finding 3)**: Electron tracks backend startup readiness (`VOICEBOT_READY` / `Application startup complete.`). The Start button in renderer remains disabled until readiness IPC is signaled, displaying status message and helpful tooltip.
4. **Replay Pagination Loop (Finding 4)**: Replay loop paginates repeatedly from `from_sequence` until `has_more === false`.
5. **Production Renderer Routing (Finding 5)**: In production Electron (`file://`), relative API URLs (`/api/...`) resolve to `http://127.0.0.1:8000/...` via `resolveUrl` and `window.voicebot.getBackendUrl()`.
6. **Revision Counts on Replay (Finding 6)**: Recomputes `revisionCounts` map from the `TranscriptAccumulator` whenever replayed segments are received.
7. **Discard Stale Session Approvals (Finding 7)**: Guards `handleApprove` and `handleReject` with `currentSessionTokenRef` check, discarding delayed responses from stopped or prior sessions.
8. **Audit Event Deduplication (Finding 8)**: Replaces nondeterministic timestamps with deterministic event IDs (`evt-audit-decision-${approval_id}-${status}`) in fixture client and deduplicates audit events in state.
9. **Live Event Stream & Auto-Reconnect (Finding 9)**: Implements `subscribeToEvents` with capped exponential backoff on connection errors, and automatically refreshes pending approvals when new audit events arrive.
10. **Strict Sidecar Readiness Matching (Finding 10)**: Strict line matching in `sidecar.cjs` requiring `VOICEBOT_READY` or `Application startup complete.` while strictly ignoring port conflict lines (`address already in use`).
11. **Unified CommonJS Production & Test Code (Finding 11)**: `main.cjs` and TypeScript modules (`bounds.ts`, `sidecar.ts`, `token.ts`) share the exact same underlying CommonJS implementations (`bounds.cjs`, `sidecar.cjs`, `token.cjs`).
12. **Multi-Monitor Display Origin Support (Finding 12)**: `getNotchBounds` correctly factors in secondary monitor coordinates: `x = display.x + round((display.width - width)/2)`, `y = display.y`.
13. **Strict Approval Status Validation (Finding 13)**: Validates `updated.status === 'rejected'` in `handleReject` (and `'approved'` in `handleApprove`); on mismatch, keeps the dialog open and displays an error message.
14. **Post-Start `transcript.error` Handling**: Both the live event stream subscription (`onEvents`) and the replay loop (`handleReconnect`) inspect and handle `transcript.error` events in the exact same manner as initial start: surfacing the user-safe message, setting UI state to `failed`, and halting normal segment display.
15. **Live HTTP Pause & Resume Lifecycle**: `HttpSessionClient` connects to backend routes `POST /api/sessions/{session_id}/pause`, `POST /api/sessions/{session_id}/resume`, and `GET /api/sessions/{session_id}` with Bearer authentication and validates returned state, maintaining `DEPENDENCY_UNAVAILABLE` strictly for real HTTP 404/501 errors.

## Setup & Run Commands

All commands are executed from `projects/sde-1-voicebot/frontend/`:

```sh
# Clean reproducible install of dependencies
npm ci

# Run complete Vitest suite (104 tests across 6 files)
npm test

# Production build and TypeScript typechecking
npm run build

# Start local web development server (browser mode)
npm run dev

# Start Electron desktop notch app with backend
npm run dev:desktop
```

*Note on Windows vs Fedora*: `npm run dev` (browser) and `npm test` are verified on Windows and Fedora. On Windows sandbox environments without an interactive desktop display session, GUI creation is tested via pure unit functions and injected mocks.

```sh
cd projects/sde-1-voicebot/backend
uv run python -m app
```
Backend starts on `http://127.0.0.1:8000`.

### Terminal 2: Frontend Desktop Notch / Browser (W6)
From repository root:
```sh
cd projects/sde-1-voicebot/frontend

# Desktop Notch App:
npm run dev:desktop

# Or standard web browser:
npm run dev
```

### Verifying Week 3 Features:
1. **Notch Window Toggle**:
   - Observe the collapsed notch pill (200×36 px) at the top centre of the screen.
   - Click the expand button (or press <kbd>Alt+N</kbd>) to reveal the expanded console (<= 480×360 px).
   - Click the collapse button (or press <kbd>Alt+N</kbd>) to return to the pill.
2. **Approval Dialog & Risk Explanation**:
   - Under Client Source Mode, select **Synthetic Fixture (Week 3 Live Notch & Progress)**.
   - Click **Start Session**.
   - Observe the **Action Approval Required** dialog explaining the exact risk.
   - Click **Reject**: Notice the step is rejected, execution is prevented, and status is logged without any tool running.

   - Observe the compact **Workflow Progress** list updating step states (`#0 step: step-read-metrics: Succeeded`, `approval_rejected: Rejected`).
4. **Reconnect & Replay**:
   - Click **↻ Reconnect** to simulate stream reconnect.
   - Missed events are replayed from `from_sequence` with zero duplicates.
5. **Privacy Settings**:
   - Verify Screen Context is **OFF** by default.
   - Toggle switch to observe safe synthetic screen context with source references.
