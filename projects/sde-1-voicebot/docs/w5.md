# W5 Backend, sessions, and shared contracts — Week 2

Related to [issue #2](https://github.com/neonjava/acd_voicebot/issues/2).

The Python package is `app`, rooted at `projects/sde-1-voicebot/backend/`. W5 provides the shared foundation, envelopes, session lifecycle management, ordered event streaming, payload limits, startup configuration validation, structured redacted logging, and FastAPI endpoints for all workstreams.

## Shared contracts (`app.contracts.common` and `app.contracts.sessions`)

### Common contracts (`app.contracts.common`)
- **`ContractModel`**: Base Pydantic v2 model configuring `extra="forbid"` to strictly reject unknown fields.
- **`EventEnvelope[T]`**: Generic event carrier with `event_id`, `event_type`, `schema_version="1.0"`, `session_id`, `correlation_id`, `timestamp` (strict timezone-aware UTC validation), `producer`, and typed `payload`.
- **`ErrorEnvelope`**: Safe error structure (`code`, `message_safe_for_user`, `retryable`, `correlation_id`, `details_redacted`). Does not leak raw tracebacks or sensitive payloads.
- **`SessionState`**: `created`, `active`, `paused`, `stopping`, `completed`, `failed`, `expired`.
- **`WorkflowState`**: `draft`, `awaiting_approval`, `running`, `paused`, `succeeded`, `failed`, `cancelled`.

### Wire session contracts (`app.contracts.sessions`)
- **`SessionCreateRequest`**: Optional `session_id`, `mode="mock"`, `initial_state` (`created` or `active`).
- **`SessionActionRequest`**: Optional `reason` field for lifecycle commands (`pause`, `resume`, `stop`).
- **`SessionStateResponse`**: Current state representation containing `session_id`, `state`, `mode="mock"`, `created_at`, `updated_at`, and `expires_at`.
- **`SessionEventStreamResponse`**: Replay batch containing `session_id`, `events`, `from_sequence`, `total_events`, and `has_more`.
- **`MockSessionResponse`**: Finite run mock session response returned by `POST /api/sessions/mock` (Week 1 baseline).

## Session service & lifecycle management (`app.sessions.service`)

The in-memory repository manages session lifecycles and enforces the documented transition matrix:

- **Legal transitions**:
  - `created` → `active`, `failed`, `expired`
  - `active` → `paused`, `stopping`, `completed`, `failed`, `expired`
  - `paused` → `active`, `stopping`, `completed`, `failed`, `expired`
  - `stopping` → `completed`, `failed`
  - Terminal states (`completed`, `failed`, `expired`) have no outgoing transitions.
- **Idempotency**:
  - Calling pause on an already paused session returns 200 without error.
  - Calling resume on an already active session returns 200 without error.
  - Calling stop on an already completed session returns 200 without error.
  - Requests carrying `Idempotency-Key` return identical cached responses on duplicate requests.
- **Expiry handling**:
  - Sessions automatically transition to `expired` when accessed after their TTL (`session_ttl_seconds`, default 3600s).
  - Explicit expiry trigger via `POST /api/sessions/{session_id}/expire`.
  - Action attempts on expired sessions fail with 410 `SESSION_EXPIRED`.

## Endpoints (`app.main`)

FastAPI application exporting `app`:

### Health & Readiness
- `GET /api/health` → `200 {"status": "ok", "mode": "mock"}`
- `GET /api/ready` → `200 {"status": "ready", "mode": "mock"}` (503 `ErrorEnvelope` if mock configuration is unavailable)

### Session Lifecycle
- `POST /api/sessions` → `201 SessionStateResponse` (supports `Idempotency-Key` header)
- `GET /api/sessions/{session_id}` → `200 SessionStateResponse` (evaluates automatic TTL expiry)
- `POST /api/sessions/{session_id}/pause` → `200 SessionStateResponse` (idempotent, supports `Idempotency-Key`)
- `POST /api/sessions/{session_id}/resume` → `200 SessionStateResponse` (idempotent, supports `Idempotency-Key`)
- `POST /api/sessions/{session_id}/stop` → `200 SessionStateResponse` (idempotent, supports `Idempotency-Key`)
- `POST /api/sessions/{session_id}/expire` → `200 SessionStateResponse`
- `POST /api/sessions/mock` → `201 MockSessionResponse` (Week 1 finite mock run)

### Event Replay and Streaming
- `GET /api/sessions/{session_id}/events?from_sequence=0&limit=100` → `200 SessionEventStreamResponse`
- `GET /api/sessions/{session_id}/events/stream` → `200 text/event-stream` (Server-Sent Events)

### Middlewares & Safety
- **Tracing**: Enforces unique `X-Request-ID` and validates/echoes `X-Correlation-ID` (1–128 ASCII chars `[A-Za-z0-9_-]`).
- **Payload Limits**: Rejects requests whose `Content-Length` exceeds `settings.max_payload_bytes` with 413 `PAYLOAD_TOO_LARGE`.
- **Structured Redacting Logger**: Replaces sensitive tokens (`Bearer ...`), credentials, raw audio bytes, transcript texts, and screen context with safe redact placeholders, formatting logs as structured JSON.
- **Normalized Errors**: Maps validation errors (422), dependency blockers (503), state conflicts (409), expired sessions (410), not found (404), and unhandled server errors (500) into typed `ErrorEnvelope` objects.
