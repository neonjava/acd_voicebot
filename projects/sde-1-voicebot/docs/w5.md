# W5 Backend, sessions, and shared contracts — Week 3

Related to [issue #69](https://github.com/neonjava/acd_voicebot/issues/69).

The Python package is `app`, rooted at `projects/sde-1-voicebot/backend/`. W5 provides the shared foundation, module gateways, session lifecycle management, event history with replay and reconnect, local authorization boundary, rate limiting, aggregated health monitoring, and FastAPI sidecar endpoints.

---

## 1. Architecture & Gateways (`app.sessions.gateways`)

The backend acts as the local hub connecting every system module through typed gateways that normalize domain errors into standard `ErrorEnvelope` structures:

- **Audio Gateway (`AudioGateway`)**:
  - Connects to `app.audio` (W1).
  - Produces audio chunks, `AudioChunkMetadata`, and ordered `SpeechEvent`s (`wake` -> `speech_start` -> `speech_end`).
  - Converts audio errors to `ErrorEnvelope` with code `AUDIO_PROCESSING_FAILED`.
- **Transcription Gateway (`TranscriptionGateway`)**:
  - Connects to `app.transcription` (W2).
  - Transcribes audio chunks using `FakeTranscriber` (or real faster-whisper when enabled).
  - Converts transcription errors to `ErrorEnvelope` with code `TRANSCRIPTION_FAILED`.
- **Reasoning Gateway (`ReasoningGateway`)**:
  - Connects to `app.reasoning` (W3).
  - Maps transcript segments to source-linked context items and invokes `reason()`.
  - Normalizes failures to `ErrorEnvelope` with code `REASONING_FAILED`.
- **Workflow Gateway (`WorkflowGateway`)**:
  - Connects to `app.agent` (W4).
  - Constructs `WorkflowProposal`, `WorkflowPlan`, and `ApprovalRequest`.
  - Invokes `app.agent.executor.execute()`, emitting safe `AuditEvent`s into the session log.
  - Normalizes execution failures to `ErrorEnvelope` with code `WORKFLOW_EXECUTION_FAILED`.

## 2. Shared Contracts (`app.contracts.sessions` and `app.contracts.common`)

### Extended Session Event Union
The event union carries events across all four connected modules:
```python
SessionEvent = Union[
    AudioChunkEvent,       # producer="audio", event_type="audio.chunk"
    TranscriptEvent,       # producer="transcription", event_type="transcript.segment" | "transcript.error"
    SpeechStreamEvent,     # producer="audio", event_type="audio.speech" (payload: SpeechEvent)
    WorkflowAuditEvent,    # producer="workflow", event_type="workflow.audit" (payload: AuditEvent)
]
```

### Approvals & Health Contracts
- **`ApprovalDecisionRequest`**: `{"decision": "approve" | "reject"}`.
- **`HealthResponse`**: `{"status": "ok" | "degraded" | "down", "mode": "mock", "modules": {"audio": ..., "transcription": ..., "reasoning": ..., "workflow": ...}}`.

## 3. Local Auth Boundary & Rate Limiting (`app.main`)

### Per-Launch Token Auth
- Electron starts the sidecar backend with environment variable `VOICEBOT_LAUNCH_TOKEN`.
- When configured:
  - Every `/api/*` endpoint except `GET /api/health` requires `Authorization: Bearer <token>`.
  - Missing or incorrect token returns `401 Unauthorized` with `code="AUTH_REQUIRED"`.
- When unconfigured (default in tests/mock mode):
  - Auth is off and `/api/ready` reports `"auth": "off"`. Existing tests run without auth headers.
- **Security**: The token is strictly redacted from logs (`Bearer [REDACTED]`) and never echoed in error responses.

### Sliding-Window Rate Limiting
- Configurable via `VOICEBOT_RATE_LIMIT_REQUESTS` (default: 100) and `VOICEBOT_RATE_LIMIT_WINDOW` (default: 60s).
- When a client exceeds the threshold:
  - Returns `429 Too Many Requests`.
  - Sends typed `ErrorEnvelope` with `code="RATE_LIMITED"` and `retryable=True`.
  - Sends `Retry-After: <seconds>` header indicating wait duration.

## 4. Endpoints

### Health & Readiness
- `GET /api/health` (Public, no auth required):
  - Returns aggregated health across all module gateways (`audio`, `transcription`, `reasoning`, `workflow`).
- `GET /api/ready`:
  - Returns readiness and auth state (`{"status": "ready", "mode": "mock", "auth": "token"|"off"}`).

### Approvals
- `GET /api/sessions/{session_id}/approvals`:
  - Returns list of pending, non-expired `ApprovalRequest`s for the session.
- `POST /api/sessions/{session_id}/approvals/{approval_id}`:
  - Body: `{"decision": "approve" | "reject"}`.
  - `approve`: Updates status to `approved`, runs the tool via W4 executor, and logs `approval_granted` + `step_succeeded` audit events.
  - `reject`: Updates status to `rejected`, cancels execution without running the tool, and logs `approval_rejected` + `workflow_cancelled` audit events.
  - Re-deciding an already approved/rejected request returns `409 APPROVAL_ALREADY_DECIDED`.
  - Deciding after `expires_at` returns `409 APPROVAL_EXPIRED`.

### Session Lifecycle & Event Replay
- `POST /api/sessions` → Create session (supports `Idempotency-Key`).
- `GET /api/sessions/{session_id}` → Fetch session state (TTL expiry evaluation).
- `POST /api/sessions/{session_id}/pause` → Idempotent pause.
- `POST /api/sessions/{session_id}/resume` → Idempotent resume.
- `POST /api/sessions/{session_id}/stop` → Stop session and mark completed.
- `POST /api/sessions/{session_id}/expire` → Explicitly expire session.
- `GET /api/sessions/{session_id}/events?from_sequence=N&limit=100`:
  - Ordered replay with no gaps or duplicates from offset `from_sequence`.
- `GET /api/sessions/{session_id}/events/stream?from_sequence=N`:
  - SSE stream that replays event history from `from_sequence`, live follows active events, and terminates cleanly on completion.

## 5. Sidecar Runner (`app.__main__`)

The backend runs as a local sidecar managed by Electron:
- Host binding is strictly locked to `127.0.0.1` (config validator rejects `0.0.0.0` or external interfaces).
- Port is read from `VOICEBOT_PORT` (default: 8000).
- Lifespan hook prints the ready notification when listening:
  ```text
  VOICEBOT_READY: http://127.0.0.1:8000
  ```
- Graceful shutdown handles `SIGTERM` and `SIGINT` (Ctrl+C) on both Linux and Windows.

## 6. Failure Path Example

### Expired Approval Decision Failure:
1. An approval request is issued with `expires_at` in the past.
2. Client sends `POST /api/sessions/{session_id}/approvals/{approval_id}` with `{"decision": "approve"}`.
3. Service checks `now >= approval.expires_at`, raises `ApprovalExpiredError`.
4. Response returns `409 Conflict` with `ErrorEnvelope`:
   ```json
   {
     "code": "APPROVAL_EXPIRED",
     "message_safe_for_user": "Approval request has expired: appr-123",
     "retryable": false,
     "correlation_id": "corr-456",
     "details_redacted": {
       "approval_id": "appr-123"
     }
   }
   ```
5. No workflow step is executed.
