# W5 Backend, Sessions, and Shared Contracts — Week 4 Hardening & Operational Runbook

Related to [issue #88](https://github.com/neonjava/acd_voicebot/issues/88).

The Python package is `app`, rooted at `projects/sde-1-voicebot/backend/`. W5 provides the backend orchestrator, conversational loop (`/turns`), browser extension WebSocket bridge (`/api/bridge`), audio capture/listen status, speech audio (`/speech`), session state machine, event history replay, launch token auth, rate limiting, OpenAPI examples, and operational runbook.

---

## 1. System Architecture & Conversation Loop

The backend orchestrates the multi-module Jarvis pipeline:
1. **Audio Capture & VAD (W1)**:
   - Tracks `CaptureStatus` (`idle`, `listening`, `capturing`, `paused`, `stopped`).
   - `POST /api/sessions/{id}/listen` starts/stops listening, emitting `audio.capture` events on the session stream.
2. **Transcription (W2)**:
   - Streams audio chunks into transcription segments. A final segment automatically triggers conversational turn processing via `process_spoken_utterance`.
   - Piper text-to-speech serves WAV audio via `GET /api/sessions/{id}/turns/{turn_id}/speech` (returns `404 TTS_UNAVAILABLE` when TTS is disabled).
3. **Reasoning & Planning (W3)**:
   - Assembles `ContextBundle` from recent turns, active app window, and observations.
   - Evaluates user intent via `RuleBasedPlanner` (mock mode) or `LLMWorkflowPlanner`.
   - Untrusted observations (screen text, notes) are segregated; prompt injections in observations never trigger action proposals.
4. **Agent & Workflow Policy (W4)**:
   - Safe tools (e.g., `system_stats`, allow-listed `open_url`) execute directly and return their outputs.
   - Consequential tools (`close_app`, `browser_task`) generate pending `ApprovalRequest`s requiring explicit client approval before execution.
5. **Browser Extension Bridge (W5)**:
   - `WebSocket /api/bridge` connects the Manifest V3 browser extension.
   - First message must be `hello` with `VOICEBOT_LAUNCH_TOKEN`; mismatch closes socket with code 1008 without logging tokens.
   - Enforces a single active extension connection and a single in-flight action with 15s timeout (`BROWSER_TIMEOUT`).
   - Action outcomes emit `browser.action` stream events without sensitive snapshot text.

## 2. API Reference & Wire Contracts

### Conversational Turns
- `POST /api/sessions/{session_id}/turns`:
  - Request: `{"text": "what's using the most RAM?", "active_app": "chrome", "active_window_title": "Google Chrome"}`
  - Response (201): `TurnResponse` (`kind`: `"answer"` | `"clarify"` | `"proposal"` | `"error"`)
  - Safe tools run directly (`turn.workflow` set). Consequential tools return `turn.approvals` with pending decisions.
  - Spoken reply provided in `spoken_text`.

### Audio Capture & Speech
- `GET /api/sessions/{session_id}/capture`:
  - Returns `CaptureStatus` (`session_id`, `state`, `source`, `wake_required`, `wake_word`).
- `POST /api/sessions/{session_id}/listen`:
  - Request: `{"action": "start" | "stop"}`
  - Updates capture status (`listening` or `stopped`) and emits `audio.capture` event.
- `GET /api/sessions/{session_id}/turns/{turn_id}/speech`:
  - Returns `audio/wav` binary stream when TTS is enabled (`VOICEBOT_TTS_ENABLED=true`).
  - Returns `404 Not Found` with `code="TTS_UNAVAILABLE"` when TTS is disabled.

### Browser Bridge WebSocket
- `WebSocket /api/bridge`:
  - Handshake: Extension sends `{"type": "hello", "token": "<VOICEBOT_LAUNCH_TOKEN>", "version": "1.0.0"}`.
  - Action dispatch: Server sends `{"type": "action", "action": BrowserAction}`.
  - Action result: Extension responds `{"type": "result", "result": BrowserActionResult}`.
  - Second concurrent connection is closed immediately with code 1008.

### Session Lifecycle & Approvals
- `POST /api/sessions` → Create session (`created` or `active`).
- `GET /api/sessions/{session_id}` → Fetch session state.
- `POST /api/sessions/{session_id}/pause` → Idempotent pause.
- `POST /api/sessions/{session_id}/resume` → Idempotent resume.
- `POST /api/sessions/{session_id}/stop` → Complete session.
- `POST /api/sessions/{session_id}/expire` → Expire session.
- `GET /api/sessions/{session_id}/events?from_sequence=N` → Replay event stream from sequence offset.
- `GET /api/sessions/{session_id}/events/stream?from_sequence=N` → Server-Sent Events (SSE) stream.
- `GET /api/sessions/{session_id}/approvals` → List pending approval requests.
- `POST /api/sessions/{session_id}/approvals/{approval_id}` → `{"decision": "approve" | "reject"}`. Deciding an expired approval returns 409 `APPROVAL_EXPIRED`. Deciding on a terminal session returns 409 `SESSION_TERMINAL_STATE`.

## 3. Operational Runbook

### Starting the Sidecar Backend
Electron spawns the backend process with a per-launch authentication token:
```bash
export VOICEBOT_PORT=8000
export VOICEBOT_HOST=127.0.0.1
export VOICEBOT_LAUNCH_TOKEN="$(openssl rand -hex 16)"
export VOICEBOT_TTS_ENABLED=false
uv run python -m app
```
Wait for the exact readiness line before connecting:
```text
VOICEBOT_READY: http://127.0.0.1:8000
```

### Authentication & Token Boundary
- Every `/api/*` request (except `GET /api/health`) must include `Authorization: Bearer <VOICEBOT_LAUNCH_TOKEN>`.
- Missing/invalid token returns `401 Unauthorized` with `code="AUTH_REQUIRED"`.
- When `VOICEBOT_LAUNCH_TOKEN` is unset (tests and mock demo), auth is off and `/api/ready` reports `"auth": "off"`.
- Logs redact all authorization tokens (`Bearer [REDACTED]`).

### Rate Limiting & Protection
- Sliding-window rate limit: `VOICEBOT_RATE_LIMIT_REQUESTS=100`, `VOICEBOT_RATE_LIMIT_WINDOW=60`.
- Exceeding limit returns `429 Too Many Requests` with `Retry-After: <seconds>` and `code="RATE_LIMITED"`.
- Payload size limit: `VOICEBOT_MAX_PAYLOAD_BYTES=1048576` (1MB). Exceeding payload limit returns `413 Payload Too Large`.

### Troubleshooting & Incident Response

| Error Code | Meaning | Resolution |
|---|---|---|
| `AUTH_REQUIRED` | Missing or invalid Bearer token | Verify Electron sidecar passed the launch token in headers |
| `RATE_LIMITED` | Exceeded 100 requests/minute | Wait for duration specified in `Retry-After` header |
| `SESSION_NOT_FOUND` | Session ID does not exist | Create session via `POST /api/sessions` before dispatching turns |
| `SESSION_TERMINAL_STATE` | Attempted action on completed/expired session | Start a fresh session; terminal sessions are immutable |
| `APPROVAL_EXPIRED` | Approval request timed out | Re-issue action from UI; approvals expire after 300s |
| `TTS_UNAVAILABLE` | Speech WAV requested while TTS disabled | Enable TTS via `VOICEBOT_TTS_ENABLED=true` with piper extra |
| `BROWSER_NOT_CONNECTED` | Browser automation attempted without extension | Connect Chromium extension to `ws://127.0.0.1:<PORT>/api/bridge` |
| `BROWSER_TIMEOUT` | Browser action took longer than 15s | Inspect browser tab responsiveness and network latency |
| `BROWSER_DISCONNECTED` | Browser tab closed during active task | Safely restarts extension connection on next interaction |
