# W1 audio and mock input — Week 1

Related to [issue #3](https://github.com/neonjava/acd_voicebot/issues/3).

The Python package is `app`, rooted at `backend/`. W2 imports
`AudioChunk` from `app.contracts.audio`, and W5 can call the source/chunker:

```python
from app.audio.chunker import chunk_pcm
from app.audio.source import make_fake_pcm

pcm = make_fake_pcm(duration_ms=1000)
chunks = chunk_pcm(pcm, session_id="session-demo", chunk_ms=20)
assert len(chunks) == 50
```

`AudioFormat` supports only 16 kHz mono signed 16-bit little-endian PCM in Week 1.
`AudioChunk` carries an internal `pcm` byte payload, a zero-based sequence ID,
and `start_ms`/`duration_ms` media times relative to the stream start. It rejects
unsupported formats, negative or noninteger counters, blank session IDs, empty
payloads, and payload lengths inconsistent with duration. At this format, one
millisecond is 32 bytes. W5 should send audio metadata to the UI, never raw PCM.

The fake source creates a repeatable integer sample pattern in memory. The
chunker splits it into whole-millisecond chunks, with a shorter final chunk when
needed. It returns an empty list for empty bytes and rejects partial samples or
partial milliseconds. It validates one stream; later integration tests must also
check consumers handle gaps, duplicates or mixed sessions appropriately.

## Run

Once W5's shared `app.contracts.common` and Python project setup are merged,
from `projects/sde-1-voicebot/backend/`:

```sh
uv sync --locked
uv run python -m app.audio.cli
uv run pytest tests/test_audio_contracts.py tests/test_audio.py
uv run ruff check .
uv run ruff format --check .
```

The CLI prints 50 lines for its default one-second stream. Each line shows
sequence, start, duration, format and byte count; no microphone is accessed.
For an invalid setting, the CLI prints a safe `AudioError` JSON object with a
fixed demo correlation ID and exits with code 2.

`AudioError` is error **data**, not an exception to raise. Constructors may raise
Pydantic `ValidationError`; the CLI turns those errors into safe, non-sensitive
output. A valid-length PCM payload can still contain arbitrary sample values;
this code cannot detect semantic audio corruption or actual speech. Mock audio
is intentionally not recorded, played or uploaded.
