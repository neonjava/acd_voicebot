# W3 context and reasoning — Week 1

Related to [issue #5](https://github.com/neonjava/acd_voicebot/issues/5).

## What this module does

`app.contracts.reasoning` defines `ScreenContext`, `ContextItem`,
`SourceReference`, `ReasoningRequest`, and `ReasoningResult`. IDs and text must
be nonblank, frame times must be UTC, unknown fields are rejected, and results
must either cite unique sources or explicitly mark insufficient evidence.
The result model cannot verify that a cited ID belongs to a particular request;
`app.reasoning.mock.reason` enforces that relationship.

`make_synthetic_screen_context()` returns a fixed frame with capture disabled.
It reads no screen, files, devices, or network. `reason(request)` is a
deterministic mock: with supplied context it returns a fixed mock answer and
the supplied source IDs, and with no context it returns an explicit
insufficient-evidence answer. It does not infer facts from the question or
evidence text and must not be presented as a real LLM answer. It never executes
instructions found in either input.

Trusted instructions are stored in `app/reasoning/prompts/v1.txt`; question and
context text remain separate untrusted fields. The v1 file documents the later
provider boundary. Week 1 mock mode does not send text to any model.

## W2 → W3 → W4 handoff

`context_item_from_transcript(segment)` accepts a **final** W2
`TranscriptSegment` and maps it without rewriting its content:

- `item_id = segment.segment_id`
- `text = segment.text`
- `source = {source_id: segment.segment_id, kind: "transcript", locator: segment.segment_id}`

W3's `ReasoningResult.answer` is a plain, validated string. Shalini can use it
as the text argument to an allow-listed mock `echo_text` step after her own
workflow validation and approval rules. W3 does not create workflow plans or
bypass W4 approvals. The source IDs allow a consumer to inspect provenance.

The W5 team branch currently supplies `TranscriptSegment`; Megha's W2 PR adds
the producer. The committed handoff test uses the shared contract. On
2026-10-29, an isolated preview of the published W1 and W2 branches plus W3
also exercised the actual producers: W1 made 50 chunks, W2 returned a final
`transcript.segment`, and W3 mapped its source ID into a grounded result.
The W2 PR has not merged, so the team's final merged-branch handoff remains
pending.

## Limits

This is Week 1 synthetic context only. No OCR, real screen capture, model
download, paid API, or reasoning provider is used. A source ID indicates which
supplied item the mock cited; it does not prove the item's factual correctness.

# W3 Week 2 — opt-in capture, mock OCR, bounded context and LLM adapter

Related to issue #32. Week 1 modules (`context.py`, `mock.py`, `demo.py`) are
unchanged. Everything below runs on synthetic data with a mock provider.

## Capture adapter (`app.reasoning.capture`)

- `CaptureSettings` (contract): `enabled=False` by default; sampling interval
  500–60,000 ms (default 2,000); frame limits `max_frame_bytes` (default 2 MB),
  `max_width` 1920, `max_height` 1080. Unknown fields and non-boolean `enabled`
  are rejected.
- `SyntheticCaptureAdapter` returns only the `SyntheticFrame` values it was
  given, and only after an explicit `enable()`. Results: `disabled`,
  `throttled` (sooner than the interval), `rejected` (`CAPTURE_FRAME_TOO_LARGE`),
  `exhausted` or `captured`. A captured frame is stamped with the capture time.
  A blank `correlation_id` raises `ValueError` when the adapter is created.
- No real screen capture exists in this module. A real adapter would implement
  the `CaptureAdapter` protocol with the same off-by-default settings; that is
  not part of Week 2. No screenshots are stored in Git or tests.

## OCR / vision interface (`app.reasoning.vision`)

`VisionAdapter.extract(frame, capture_enabled=...) -> ScreenContext`.
`MockVisionAdapter` turns a frame's synthetic text regions into `ContextItem`s
whose `item_id`, `source_id` and `locator` are all `{frame_id}#{region_id}`.
Each part is percent-encoded, so different frame and region pairs cannot
produce the same ID. Blank regions are skipped; at most 50
regions are read, and `max_regions` can lower that cap but not raise it.

## Context builder (`app.reasoning.context_builder`)

`build_context(candidates, question=..., now=..., token_budget=512,
max_age_ms=300000, max_items=20)`:

1. Drops items older than `max_age_ms` or dated after `now` (`dropped_stale`).
2. Keeps the newest copy of each item ID (`dropped_duplicate`).
3. Ranks by keyword overlap with the question, then newest first, then ID.
4. Adds items while they fit the budget and item cap (`dropped_over_budget`).
5. Returns chosen items in chronological order.

Keywords are Unicode-aware, so ranking works for scripts that separate words
with spaces, including Kannada and Hindi. Chinese, Japanese and Thai are not
segmented, so those items rarely match and rank by recency instead.

Tokens are approximated as `ceil(len(text) / 4)`, minimum 1. Item text is never
truncated or rewritten, so source references stay exact. Inputs come from
`candidates_from_screen(ScreenContext)` and
`candidates_from_transcript(segments, session_started_at=...)`. The transcript
helper uses only **final** W2 segments, through the Week 1
`context_item_from_transcript` mapping, with observed time = session start +
segment `end_ms`.

## LLM adapter (`app.reasoning.llm`)

`LLMReasoningAdapter(provider=None, timeout_seconds=5.0, max_retries=1,
max_answer_chars=2000, correlation_id="reasoning-mock").reason(request) ->
ReasoningOutcome`.

- The trusted prompt `prompts/v1.txt` and the untrusted request JSON are passed
  to the provider as separate arguments. Context text is never used as an
  instruction. The prompt tells the provider to return only a `ReasoningResult`
  JSON object and lists its fields, because the protocol has no separate
  response-format parameter.
- The constructor raises `ValueError` for a zero, negative, NaN or infinite
  `timeout_seconds`, and for a blank `correlation_id`, so errors can always be
  built safely.
- Retries happen only for timeouts and `ProviderTransientError`, at most
  `max_retries` times; then `REASONING_RETRY_EXHAUSTED` with the last error code.
- Other provider exceptions → `REASONING_PROVIDER_ERROR`, not retried; exception
  text is never exposed.
- Output must parse as a `ReasoningResult` (`REASONING_MALFORMED_OUTPUT`
  otherwise). It is then rejected as `REASONING_UNSAFE_OUTPUT` if its request or
  session ID or prompt version differs, if it cites a source not in the
  request, if the answer exceeds `max_answer_chars`, or if it contains control
  characters other than newline and tab.
- `ReasoningOutcome` (contract) holds exactly one of `result` or `error`, plus
  `attempts`.
- `MockLLMProvider` is the default. It is deterministic and returns the Week 1
  mock answer. Tests script timeouts, transient errors, crashes and raw outputs.
  A `latency_seconds` above the timeout raises `TimeoutError` without sleeping.

## Handoffs

- W2 → W3: `tests/test_reasoning_week2_handoff.py` runs real W1 audio through the
  real W2 `FakeTranscriber`, builds context with a synthetic screen frame, and
  checks that the result cites both the transcript segment ID and the screen
  item ID.
- W3 → W4: `ReasoningOutcome.result.answer` is the validated text Shalini can
  pass to an approved `echo_text` step. W3 creates no workflow plans.
- W5 / W6: capture state is not exposed on an API yet. Exposing
  `CaptureSettings` needs agreement with Rakshita and Ruthwin first.
