# W3 context and reasoning — Week 1

Related to [issue #5](https://github.com/neonjava/acd_voicebot/issues/5).

## What this module does

`app.contracts.reasoning` defines `ScreenContext`, `ContextItem`,
`SourceReference`, `ReasoningRequest`, and `ReasoningResult`. IDs and text must
be nonblank, frame times must be UTC, unknown fields are rejected, and results
must either cite unique sources or explicitly mark insufficient evidence.
The result model cannot verify that a cited ID belongs to a particular request;
`app.reasoning.mock.reason` enforces that relationship.

`make_synthetic_screen_context()` returns a fixed frame with capture disabled.
It reads no screen, files, devices, or network. `reason(request)` is a
deterministic mock: with supplied context it returns a fixed mock answer and
the supplied source IDs, and with no context it returns an explicit
insufficient-evidence answer. It does not infer facts from the question or
evidence text and must not be presented as a real LLM answer. It never executes
instructions found in either input.

Trusted instructions are stored in `app/reasoning/prompts/v1.txt`; question and
context text remain separate untrusted fields. The v1 file documents the later
provider boundary. Week 1 mock mode does not send text to any model.

## W2 → W3 → W4 handoff

`context_item_from_transcript(segment)` accepts a **final** W2
`TranscriptSegment` and maps it without rewriting its content:

- `item_id = segment.segment_id`
- `text = segment.text`
- `source = {source_id: segment.segment_id, kind: "transcript", locator: segment.segment_id}`

W3's `ReasoningResult.answer` is a plain, validated string. Shalini can use it
as the text argument to an allow-listed mock `echo_text` step after her own
workflow validation and approval rules. W3 does not create workflow plans or
bypass W4 approvals. The source IDs allow a consumer to inspect provenance.

The W5 team branch currently supplies `TranscriptSegment`; Megha's W2 PR adds
the producer. The committed handoff test uses the shared contract. On
2026-10-29, an isolated preview of the published W1 and W2 branches plus W3
also exercised the actual producers: W1 made 50 chunks, W2 returned a final
`transcript.segment`, and W3 mapped its source ID into a grounded result.
The W2 PR has not merged, so the team's final merged-branch handoff remains
pending.

## Run

From `projects/sde-1-voicebot/backend/`:

```sh
uv sync --locked --extra dev
uv run pytest tests/test_reasoning.py tests/test_reasoning_contracts.py tests/test_transcript_to_reasoning.py
uv run python -m app.reasoning.demo
uv run ruff check .
uv run ruff format --check .
```

The demo prints `capture_enabled=False`, prompt version `v1`, the fixed mock
answer, and `source_ids=screen-status`. It does not print or save screenshots.
`tests/fixtures/reasoning/result.json` is validated against the same mock
function to prevent fixture drift.

## Limits

This is Week 1 synthetic context only. No OCR, real screen capture, model
download, paid API, or reasoning provider is used. A source ID indicates which
supplied item the mock cited; it does not prove the item's factual correctness.
